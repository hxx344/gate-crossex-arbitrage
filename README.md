# Gate CrossEx · 永续价差套利模拟

接收 [Market Monitor](https://github.com/hxx344/market-spread-monitor) 发现的价差，核对 Gate CrossEx 合约目录，在真实公共盘口深度上模拟开仓、持仓估值和平仓。作为独立模块接入 [Project Aggregation](https://github.com/hxx344/project-aggregation) 工作台，也可以单独访问。

**当前版本只做本地模拟，不发送真实订单，不连接交易账户，不需要交易所 API Key。** Gate CrossEx 的接入是读取官方合约规则并核对执行范围；成交记录由本模块模拟，不是 Gate 沙盒订单。支持公共资金费账本及分腿、分批、延迟和拒单情景；不模拟真实账户保证金、强平、排队优先级或市场冲击。

## 联动方式

```text
Market Monitor 公共行情与价差发现
  → /api/monitors/perpetual/opportunities-v2
  → CrossEx 合约可用性、数量与额度检查
  → 七所公共深度与 USDC / USD 汇率复核
  → 模拟双腿开仓 → 持仓估值 → 模拟平仓 → SQLite 记录
  → 工作台独立入口与摘要（不计入真实资产）
```

- 支持 Binance、Bybit、OKX、Gate、Kraken、Hyperliquid、Lighter 七所，明确排除 Deribit。仅同币种、单位为 1 的普通加密永续；支持集合由 Monitor 当前身份资料与 CrossEx 合约目录共同决定。未知标的、倍数、盘前、非加密及已知下架合约不参与开仓。具体契约见 [联动接口](https://github.com/hxx344/market-spread-monitor/blob/main/docs/CROSSEX_SIGNALS.md)。
- Binance / Bybit / OKX 支持 USDT、USDC；Gate 为 USDT；Kraken 为 USD；Lighter 为 USDC。Hyperliquid 普通永续用 USDT 报价、USDC 结算，HYPE / PURR 为 USDC 报价与结算。报价、结算和保证金币种分别保留，不互相替代。
- USDC / USDT 取 Gate 现货买卖价；USD / USDT 取 Kraken 的 USDT / USD 盘口倒数并反转买卖方向。缺失、倒退、超过 3 分钟的汇率不能用于新模拟，绝不默认兑价为 1。等基础币数量不能对冲结算币汇率风险，本版本没有模拟换汇深度或外汇对冲。
- Gate / OKX 公开深度的合约张数换算为基础币数量。CrossEx 的订单数量规则已按基础币计量，不重复乘已弃用的 contract_size。官方目录明确为 null 的最小名义额或最大市价数量，会显示“未提供”，不会声称通过该项校验；本地额度、最小数量、步长和深度限制仍执行。
- 每 2 秒独立后台读取信号、每 5 秒推进模拟；慢合约目录、资金费或模拟深度请求不阻塞行情刷新。同一时刻只保留一个行情读取请求，修改连接设置后忽略旧请求的结果。Gate 合约目录每 5 分钟更新，短暂失败可使用不超过 15 分钟的缓存并显示状态。打开浏览器不是后台运行条件。
- 自动模拟默认关闭。可手动开平仓，或设置预算、手续费、滑点上限、净价差门槛、止盈止损、最长持有时间后启动自动模拟。
- 默认保留同步全量模拟：每次开平仓读取两腿公共盘口，全量成交才记账。另可选分阶段模拟：先预留预算，再按公共深度分腿、分批推进，记录部分成交、未知回报、拒单修复和撤销确认。两种模型都不代表交易所提供原子双腿订单。
- 每腿按原始盘口时间检查，超过 10 秒、未来超过 1 秒或两腿相差超过 5 秒就拒绝。断线保留旧估值并明确过期，不把旧报价变成新收益。
- 每币种最多一个活动持仓；请求、信号、平仓后冷却持久去重，重启继续保存的持仓与自动模拟设置。

## 现货与充提资格贯穿发现和执行

Monitor 的“双方有现货且充提正常”仍为可选筛选，默认关闭。开启后，Monitor 排名和推送共用双边可交易现货、相同资产的共同网络及双方双向充提证据；当前公开资料覆盖 Binance、Gate，其他平台未知时排除。CrossEx 显示共同网络、核验和到期时间，关闭或旧来源未提供策略时明确标为未核验。资格通过的机会优先排序，再按预算净价差排序；通过资格仍须复核独立深度、数量、费用与额度。

CrossEx 手动、自动开仓在读取深度前后都重新读取 Monitor，校验当前屏蔽名单、证据有效期以及同一方向和合约身份是否仍在最新机会中。浏览器短期旧信号仅在原到期前且最新同向机会仍合格时允许继续；被撤回、屏蔽、网络不匹配或现货/充提证据失效均不能沿用旧信号。曾收到筛选策略的连接，后续缺少策略时停止新仓，该约束在重启后仍保留。旧版从未提供策略的来源保持原模拟兼容，并显示未核验；建议先升级 Monitor，再升级 CrossEx。

分阶段任务每次生成新成交回执前，以最新同向信号重新校验资格，深度返回后再次检查；不使用创建任务时已经过期的信号来授权后续分片。“只暂停新仓”也停止已有开仓任务新增分片。已经接受的回执（包括未知状态）仍先对账且只记账一次；取消任务、持仓估值和平仓继续使用保留报价和独立深度。资格撤回可能保留已成交的单腿敞口，可在持仓页撤销剩余任务后退出。

资格来自 Monitor 最近一次成功公开采集，最长有效 180 秒，不能证明交易所此刻仍开放充提；执行前刷新的是 Monitor 已采集证据，不逐单向交易所查询充提。最新机会因推送上限等原因不再列出时也保守停止新成交。模拟未加入真实转币、费用或到账时间模型。

## 在工作台使用

1. 更新后左侧会出现 **Gate CrossEx**。默认页面/接口为 `http://127.0.0.1:3200`，适配器 `standard`，访问方式 `proxy`。
2. 在服务器查看本模块首次启动日志：`sudo journalctl -u gate-crossex-arbitrage --no-pager -n 30`。用户名为 `admin`，密码独立于工作台与 Monitor。在工作台“项目管理”保存它，以后可自动进入。
3. 进入 CrossEx 的“连接与设置”，填写价差服务地址 `http://127.0.0.1:3000` 和 **Market Monitor 的网页登录用户名、密码**。只有同机回环地址被接受；更换目标地址或用户名会清除旧密码。
4. 检查来源状态，按模拟用途调整参数，然后选择机会模拟开仓或启动自动模拟。

继续使用已有的工作台 SSH 转发 `3100`，不需要新增转发。模拟余额和盈亏单独展示，不进入 Asset Ledger 总额。若单独使用此模块，可转发 `3200`，浏览器会要求输入模块 Basic 登录信息。

“暂停全部自动”停止自动开仓、自动风控退出和自动任务的新阶段；已接受的模拟成交仍需对账，手动任务与手动平仓仍可用。“只暂停新仓”同时禁止手动、自动新开仓，继续管理已有持仓。已有持仓保存开仓时的费用、滑点、止盈止损和时限规则；分阶段任务也保存场景和批量参数。Monitor 离线不阻止到期持仓通过独立交易所深度退出；深度、身份或汇率不满足要求时保留敞口、记录失败，不虚构成交。

## 费用与收益口径

默认参数仅用于模拟：单腿 100 USDT、同时最多 3 组、双腿总名义额上限 1000 USDT、每次手续费 6 bp、每次滑点上限 5 bp、预算净价差至少 20 bp。1 bp = 0.01%，这些不是个人 CrossEx 账户费率。额度是名义额预算，不是账户权益或杠杆保证金模型。

毛价差 = `(空腿买一 / 多腿卖一 − 1) × 10000 bp`；机会的预算净价差减去四次手续费和四次滑点预算。复核成交深度后，入场均价已经包含逐档滑点，仅另留两次退出滑点预算；不会把已体现在均价里的滑点重复扣费。

每腿先按原始合约价格计算损益：多腿为 `数量 × (平仓价 − 开仓价)`，空腿为 `数量 × (开仓价 − 平仓价)`。再按各腿结算币换算为 USDT，盈利用买价、亏损用卖价；开仓费用按入场汇率保存，平仓费用按退出汇率计算。汇率影响是毛价格损益相对于入场参考汇率的折算差，已经包含在毛损益中；不对完整开平仓本金分别换算后相减。数量步长、撮合和费用采用独立 Decimal 运算，持久化保留精确字符串。

手续费按“合约覆盖 → 交易所默认 → 原有 feeBps”解析，保存多腿/空腿各开平两次费率、来源与更新时间。当前深度成交均为 taker；maker 配置仅保留资料，不宣称模拟被动挂单成交。入场快照不会被以后修改的费率覆盖。

资金费保留原生周期、下一结算时间及源时间，按照实际数量历史结算。完整确认、已知部分和持有期估算分别显示；缺历史价格、汇率或覆盖时合计为未知。Kraken 按持有时段积分；Hyperliquid/Lighter 缺历史 oracle/index 价格时不伪造确认金额。已有旧版持仓保留原损益并标记 legacy，不倒填零资金费。来源与规则见 [资金费资料](docs/funding-sources.md)。工作台原盈亏指标继续使用不含资金费口径，页面另显示含资金费结果。

持仓同时显示 BBO 参考估值与独立深度支持的退出量、均价滑点和收益。深度默认每 15 秒复核，盘口超过 10 秒即标旧；成交后立即使旧数量快照失效。部分可成交只报告数量，不显示全仓退出净值。

净值与持仓价差默认每 15 秒采样、北京时间显示。净值是累计模拟盈亏，回撤按 USDT 金额计算，没有虚构初始本金百分比；最不利价差为相对入场价差的最大扩大。缺失点断线、不插值。每条序列保留最近 5000 点并清除超过 90 天的数据，页面最多约 600 点保留极值和缺口，持仓轨迹展示最近 50 组。最近 200 笔平仓可查，累计指标包含全部记录；最大回撤是已采集点的结果，不能覆盖停机及缺失时段。

## 分阶段模拟与恢复

设置中可选择普通分批、部分成交、空腿拒绝、空腿回报未知、延迟撤销及首次撤销失败；固定种子使同一输入序列可复现。配置的延迟是阶段最短等待时间，实际推进受默认 5 秒后台周期与数据请求耗时影响，不是毫秒级交易延迟回测。每批金额是目标，避免违反目录最小数量或金额时允许合并尾批。

本地成交回执先持久化，再在单一事务中更新持仓、费用和记账标记；重启先对账，不重复累计。未知回报不会直接重发。部分成交沿原委托剩余量继续，残余量不能构成有效新委托时暂停等待处理。撤销会先确认已接受的成交，已有敞口保留，可重试修复或单独平仓。自动修复达到次数上限停止；取消自动平仓后下一次风控检查仍可重新触发。

任务记录未对冲持续时间、修复手续费及相对首轮深度的不利价差成本、已观察最差损失。修复成本仅用于复盘，实际成交价和费用已进入账本，不重复扣减。待成交预算与已有持仓共同计入额度；分批退出释放对应数量的预算。

## 工作台摘要与页面读取

`GET /api/hub/summary?schemaVersion=2` 只读当前持仓、聚合盈亏和行情状态，不创建完整机会、历史或事件列表。`health` 区分 offline、partial、stale 和 online，并具体说明盘口或目录问题。只要仍有来自在线交易所的有效行情，摘要时间取最新有效盘口的源时间，并受行情包生成时间限制；部分盘口过期继续标记 partial，避免一条旧盘口把整个模块误判为 stale。若显示浮动盈亏，摘要时间还受这些持仓最早估值时间限制，其他币对的新报价不能延长旧盈亏的有效期。持仓估值过期时浮盈为 null，全部盘口过期仍为 stale，读取失败仍为 offline；10 秒时效及交易、持仓估值校验不变。不能用请求时间或心跳刷新旧数据。无参数继续提供 v1 摘要。

后台每 2 秒读取一次 Monitor，独立于每 5 秒的模拟检查；慢请求共享同一次读取，不堆积。页面每 2 秒检查一次状态，但历史和事件只在“记录与收益”打开时读取；随后按 `historyVersion` 省略未变化的历史，服务重启自动重建版本。默认 `/api/state` 保留完整返回，`history=0` 为紧凑读取。手动刷新与轮询共享请求，12 秒超时后释放轮询，即使底层请求未响应取消也能恢复；保存或模拟后的刷新取消旧读取并忽略乱序响应。隐藏、离开模块和工作台握手前停止前端读取，恢复立即刷新；后台模拟持续按既有设置运行。

页面以服务器时间加单调流逝时间判断过期，并保守计入请求耗时；不受浏览器系统时钟偏差影响。持仓分别按原始盘口时间老化，保留旧数值并说明缺失盘口、哪一腿过期、双腿不同步、连接或汇率问题，同时显示双腿盘口时间。旧估值不进入浮盈合计。来源显示最近读取成功时间及耗时，它们仅用于诊断，不延长报价有效期。原有 10 秒报价时效、5 秒双腿同步要求及平仓深度复核保持不变。

工作台握手成功后提供“在 Monitor 查看”。Monitor 的“在 CrossEx 查看”通过 `symbol/longExchange/shortExchange` 定位同一方向，独立打开也可从 URL 恢复筛选；所有跳转只调整页面，不开仓、不改设置。桥严格核对父窗口、独立代理主机名、协议和端口。成功保存设置或模拟操作后通知工作台刷新摘要。

Monitor 的 gzip 响应由 HTTP 客户端自动解压一次，大小限制针对解压后内容。公开构建产物 `/assets/<name>-<hash>.js/css` 明确返回一年 immutable 缓存；HTML 和 API 保持 no-store。工作台仅缓存经过该标记的构建资源。

升级仍使用上方一键命令；本次增加固定版本 decimal.js，安装器按依赖摘要更新。旧配置自动补默认字段，SQLite 增量创建执行与采样表，配置和原模拟记录保留。无内容变化的重复升级仍跳过安装、检查、构建和重启。
